handoff.

A message between two agents that cannot be lost because the receiver happened to be busy. Three directories, one atomic rename: not delivered becomes a state instead of an error.

The whole protocol

No daemon, no port, no database. The queue is a directory; state transitions are renames, and a rename inside one filesystem is atomic.

Eight tools

Each one is a single verb; none of them guesses.

handoff_postpublish a message, idempotent by key
handoff_takeclaim one with a lease, exclusive while it lives
handoff_ackfinish it
handoff_nackreturn it, or park it in dead
handoff_sweeprecover messages from consumers that died
handoff_listinspect queue / leased / done / dead
handoff_statstotals per channel and state
handoff_waitblock briefly, return the message already leased

Limits, stated plainly

  • Atomicity holds inside one filesystem. Across machines you need correct rename semantics (NFS yes, some FUSE mounts no).
  • Delivery is at-least-once. A consumer must tolerate redelivery; the key is its idempotency token.
  • Polling, not push. wait is a bounded wrapper around take.
  • Plain text files. A bus for trusted local agents, not a secure transport.
